# 검증 근거를 자기 말로 설명하기

학습·복기·설명 연습을 요청했을 때만 사용한다. 일반 업무의 검증이나 제출을 사용자 답변 대기 때문에 멈추지 않는다. 목표는 AI가 만든 설명의 암기가 아니라 사용자가 실제로 판단·확인한 내용과 그 한계를 드러내는 것이다.

- 사용자의 최초 판단·설명을 보존한 뒤 피드백한다. 답을 보기 전 새로 판단하는 연습인지, 이미 본 해설을 재설명하는 연습인지 구분한다. 사용자가 해설부터 요청하면 그 순서를 따른다.
- 대표 사례를 고를 때 정상·경계·예외 중 현재 부족한 판단을 드러내는 사례를 선택한다. 세 건이라는 수를 항상 강제하지 않는다.
- 다음 질문 중 필요한 것을 묻는다. 목적과 완료 기준은 무엇인가? 어떤 자료의 어떤 값에 무슨 규칙을 적용했나? 무엇을 무엇과 비교했나? 어느 근거로 판단을 바꾸거나 유지했나? 어떤 새 사실이 나오면 선택이 달라지나?
- 짧은 답변만으로 이해 부족을 단정하지 않는다. 비교 대상이나 추론이 빠졌으면 한 번 더 구체적으로 설명하도록 돕는다. 실제로 하지 않은 검증·수정 경험을 만들어 채우지 않는다.
- 피드백은 원문·규칙과의 일치, 근거 연결, 본인과 AI의 역할, 한계·재검토 조건을 기준으로 한다. 공식 평가 기준이 제공되지 않으면 참고 피드백임을 명시하고 임의 점수를 공식 점수처럼 제시하지 않는다.
- 보완 설명과 최초 설명을 구분해 남긴다. 다음 적용 행동은 실제로 빠졌던 핵심 행동을 고른다. 전이가 필요한 경우 다른 입력의 새 사례에서 적용해 보되, 사용자가 요청한 연습 범위를 넘겨 반복을 강요하지 않는다.

간단한 기록은 `최초 설명 → 빠진 근거 → 보완 설명 → 다음 사례에 적용할 행동`이면 충분하다. 화면을 가린 구두 설명을 관찰하거나 녹음하지 않았다면 서면 답변만 평가했다는 범위를 보존한다.
