# 해결 방안 도출·검토·선택 지원

AI는 대안과 선택의 대가를 드러내고 조건부로 추천한다. 사용자는 우선순위, 감수할 위험, 미확인 사항을 검토해 최종 선택한다. 한국어를 기본으로 하며 사용자가 지정한 언어와 형식을 따른다.

## 출발점

기존 문제 정의와 요구사항, 사용자 결정이 있으면 활용한다. 별도 문서나 다른 스킬의 실행을 필수로 요구하지 않는다. 목적, 필수 조건, 제약, 성공 기준을 비교에 필요한 만큼 확인한다. 원인 가설이나 AI의 개선 제안을 확정된 조건으로 취급하지 않는다.

사용자가 이미 정한 방법과 범위를 보존한다. 비교를 요청했다면 선택 근거를 검토하되, 구현만 요청했다면 불필요하게 재선정 절차를 시작하지 않는다.

## 대안 도출

- 요구사항을 충족할 가능성이 있는 실질적으로 다른 방법을 만든다. 이름이나 도구만 다른 변형을 별개 대안으로 부풀리지 않는다. 수동 절차, 기존 도구 활용, 작은 변경도 문제에 적합하면 고려한다.
- 각 대안의 작동 방식, 기대 이점, 필요한 전제와 자원, 알려진 제약을 설명한다. 후보 수는 결정의 복잡도에 맞추고, 비교용으로 명백히 열등한 대안을 억지로 추가하지 않는다.
- 각 Solution을 `문제·Pain → Mechanism → Opportunity → 구체적인 방법 → 기대 변화`와 연결한다. 동일한 개입 지점을 다른 방법으로 바꾸는 대안과 개입 지점 자체가 다른 대안을 구분한다. 개입 가설이 없으면 자료에서 가능한 연결을 잠정으로 적고, 별도 스킬 실행을 필수로 요구하지 않는다. 원인·개입 지점이 반박되면 기능 세부 조정만 계속하지 말고 문제 정의로 돌아갈 조건을 남긴다.
- 명시된 필수 조건을 충족하지 못하는 대안은 그 사실을 표시한다. 큰 장점이나 총점으로 필수 조건 위반을 상쇄하지 않는다. 조건 변경이 필요하면 변경 제안으로 분리한다.

## 비판적 검토

대안을 만든 뒤 검토 관점으로 다시 읽는다. 선택을 바꿀 수 있는 약점을 찾되 반대를 위한 반대를 하지 않는다. 별도 에이전트를 쓰지 않았다면 독립 검토를 거쳤다고 표현하지 않는다.

- **충족 여부:** 핵심 요구사항을 빠뜨렸거나, 현상의 일부만 해결하는가?
- **가정과 증거:** 성공에 필요한 전제가 확인됐는가? 주장에 맞지 않는 근거나 아직 확인하지 못한 정보가 있는가?
- **비교의 공정성:** 같은 기준을 모든 대안에 적용했는가? 선호하는 방법에만 낙관적인 가정이나 더 많은 검토 시간을 적용하지 않았는가?
- **리스크와 비용:** 어떤 조건에서 실패하며, 누구에게 어떤 영향이 있는가? 필요한 경우 발생 가능성, 영향, 완화 방법과 남는 위험을 구분한다. 근거 없는 확률·비용 수치를 만들지 않는다.
- **되돌릴 수 있는 정도:** 도입 후 변경·중단·복구할 수 있는가? 전환 비용, 운영 부담, 의존성이 선택을 바꾸는가?

비판은 가능한 범위에서 근거, 의사결정에 미치는 영향, 확인·완화 방법을 연결한다. 미확인 가능성은 가설로 표시하고, 중요도가 낮거나 선택을 바꾸지 않는 위험을 끝없이 늘리지 않는다. 장점도 같은 수준으로 검증한다.

업무 개선 대안에서는 **역할별 업무 변화**를 살핀다. 누구의 일이 줄고, 누구에게 입력·갱신·검수·보완 추적·예외 처리·유지 업무가 생기는지 현재 방식과 비교한다. 문의 대응 시간 감소를 전체 업무 시간 감소로 간주하지 않는다. 관련 역할만 검토하며, 전체 시간 비증가 같은 기준은 사용자 요구이면 보존하고 새로 제안할 때는 제안으로 표시한다. 담당·권한·인계·갱신 책임이 합의되지 않았다면 도입 전제로 남기고, 당사자 동의나 운영 가능성을 만들어 확정하지 않는다.

## 트레이드오프와 추천

작은 결정은 짧은 비교로 충분하다. 복잡하면 대안별 요구사항 충족, 이점, 비용·리스크, 가정·미확인 사항, 유리한 조건을 표로 정리한다. 근거와 불확실성을 함께 보여준다.

리스크가 가장 작은 방법과 이점이 가장 큰 방법이 다를 수 있다. 사용자가 정한 우선순위를 적용하고, 우선순위가 미정이면 어떤 가치 판단에 따라 선택이 달라지는지 설명한다. 가중치나 점수를 임의로 정해 객관적 최적해처럼 제시하지 않는다. 정량 비교가 유용하면 기준값·계산 근거·가정을 공개한다.

추천할 때는 다음을 명확히 한다.

- 어떤 조건과 우선순위에서 이 대안이 유리한가.
- 선택으로 얻는 이점과 포기하거나 감수하는 것은 무엇인가.
- 어떤 미확인 가정이나 새 증거가 추천을 바꿀 수 있는가.

## 사람의 질문과 최종 선택

추천과 사용자의 확정 선택을 구분한다. 다음 실행에 최종 선택이 필요하고 아직 없다면 결정을 좌우하는 질문을 짧게 제시하고 해당 실행은 사용자 판단을 기다린다. 선택에 의존하지 않는 비교 문서 작성·근거 검증 등 이미 요청된 작업은 계속한다. 선택 권한을 명시적으로 위임받은 경우에는 그 범위에서 결정하고 근거를 남긴다. 아직 선택하지 않은 대안의 실행을 임의로 시작하지 않는다.

사용자는 후보를 고르는 것뿐 아니라 우선순위 변경, 새 대안 요청, 가정에 대한 질문, 작은 실험, 보류를 선택할 수 있다. 사용자 질문이나 추가 증거가 들어오면 영향을 받는 비교와 추천을 갱신한다. 사용자가 이미 확정한 사항을 반복해서 재승인받지 않는다.

작은 실험으로 중요한 불확실성을 줄일 수 있으면 확인할 가정, 최소 실험, 관찰할 결과, 선택을 바꾸는 기준을 제안한다. 확정된 요구사항과 관찰 결과를 연결하고, 실제로 수행하지 않은 실험을 검증 완료로 표현하지 않는다.

## 업무 효과를 비교할 때

효과 확인이 선택을 좌우하면 아래 항목 중 필요한 내용을 구체화한다. 모든 대안에 시범 운영이나 정량 실험을 강제하지 않는다.

- **가설과 최소 변경:** 어느 원인에 어떤 변경을 가해 무엇이 달라질 것으로 보는가. 기능이 동작하는 시험과 현업의 효과 확인을 구분한다.
- **비교 자료:** 현행 기준값과 변경 후 결과를 어느 대상·기간·업무 단계에서 얻는가. 사례의 복잡도·업무량·담당자 차이를 남긴다. 자료가 없으면 효과 수치를 계산하지 않는다.
- **지표 정의:** 계산식·단위·분모·포함·제외 기준을 전후에 같게 둔다. 전체 문의와 같은 상태의 반복 문의를 구분한다. 직접 작업시간과 응답 대기시간은 분리하고 노동시간처럼 합산하지 않는다.
- **수집과 운영:** 무엇을 어디에 누가 언제 기록하고 검토할지 정한다. 종료일까지 미완료인 건을 조용히 제외하지 말고 후속 관찰·별도 집계 등 처리 방법을 제안한다. 기록·검토 부담도 비용에 포함한다.
- **판단 조건:** 유지·수정·중단할 관찰 결과와 재검토 시점을 정한다. 임계값은 요구·합의·제안을 구분한다. 문의는 줄지만 총 부담이 늘거나 잘못된 상태가 전파되는 경우 등 선택을 바꿀 조건을 다룬다.

필요하면 `가설·변경 | 지표 정의 | 비교 대상·기간·기준값 | 수집 담당·방법 | 미완료 처리 | 유지·수정·중단 조건`으로 정리한다. 작은 표본이나 단순 전후 차이를 일반적 인과 효과로 단정하지 않는다. 현장 운영이 불가능한 과제에서는 계획과 현재 검증 가능한 범위까지 제시한다.

선택이 확정되면 선택한 방법, 선택 이유, 감수한 트레이드오프, 남은 가정과 재검토 조건을 간결하게 남긴다. 이후 실행 계획·구현 단계로 전달한다. 선택이 미정이면 비교 결과와 미결정 사항을 남겨 다음 대화에서 이어갈 수 있게 한다.

## 입력과 Markdown 출력

- **입력:** 02-problem-definition.md의 P/M/O-ID, 03-requirements.md의 R-ID·검증 기준·충돌, 사용자 우선순위·선택. 동등한 직접 자료도 입력으로 사용할 수 있다.
- **출력:** `04-solution-evaluation.md`. S-xx 대안과 P/M/O/R 연결, 추천·사용자 선택의 구분, X-xx 실험 계획, 남은 가정·재검토 조건을 산출물 작성과 verify-work-results에 전달한다.
- 단계 결과를 작성할 때 [출력 양식](assets/output-template.md)을 읽고 고정된 절·열에 맞춰 채운다. 사용자 지정 형식이 있으면 우선한다. 해당 없는 항목은 이유와 함께 표시하고 모르는 값을 만들어 채우지 않는다. 앞 단계 파일이 없어도 동등한 직접 자료를 입력표에 기록해 독립적으로 진행한다.
- 저장 위치는 사용자 지정 경로 또는 현재 프로젝트의 `artifacts/<작업명>/`이다. 같은 과제의 문서를 함께 두고 입력은 상대 링크·사용 버전·항목 ID로 연결한다. 쓰기가 불가능하거나 파일 생성을 원하지 않으면 같은 형식의 Markdown을 대화에 제공하고 저장했다고 하지 않는다. 스킬 설치 폴더에 사용자 결과를 저장하지 않는다.
- 관련 입력 문서와 필요한 원자료를 실제로 읽는다. 기존 ID는 유지하고 출처 파일로 구분한다. 새 항목만 ID를 추가하며, 근거의 종류·미확인·원인 가설 상태를 다음 단계에서도 보존한다. 인용된 요약만으로 원문을 대조했다고 하지 않는다.
- 최초 문서는 `r1`, 의미 있는 갱신은 리비전을 올리고 변경 이유를 남긴다. 이전의 최초 판단·사용자 설명을 지우지 않는다. 사용한 입력 버전이 바뀌면 영향받는 항목을 재검토하고, 확인 전에는 해당 연결을 `재검토 필요`로 표시한다. 실행하지 않은 후속 문서까지 자동 갱신했다고 하지 않는다.
- **사용자 검토 상태**는 기본 `미검토`다. 문서 내용에 관한 실제 사용자 피드백이 있을 때만 갱신한다. 진행 위임만으로 검토 완료로 바꾸지 않으며, 문서 완성·AI 검증·사용자 검토·최종 선택을 구분한다. 선택·위임은 해당 판단의 별도 항목에 근거와 함께 기록한다. 단계 결과 링크와 핵심 결론·확인할 점을 사용자에게 보여준다. 매 단계의 승인을 새 필수 절차로 만들지 않고, 이미 허용된 후속 작업은 계속한다.
- 대화 중의 짧은 질문마다 새 파일을 만들지 않고 해당 단계 문서를 갱신한다. 아직 수행하지 않은 단계의 문서를 미리 완료 상태로 만들거나 빈 양식 다섯 개를 강제로 생성하지 않는다.
