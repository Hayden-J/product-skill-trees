# PNG·텍스트·단계 표로 설계를 설명하기

기본은 같은 흐름을 PNG 이미지, `text` 코드 블록, 단계 표로 제공하는 것이다. 이미지가 표시되지 않아도 문서만 읽고 정상·실패 경로를 따라갈 수 있어야 한다. 아래 예시는 설명용이며 실제 요구나 구현을 대신하지 않는다.

## 기본: 핵심 처리 흐름

먼저 설계 문서의 텍스트·표로 단계와 분기를 정하고 이를 PNG로 그린다. 한 그림은 첫 사용자 흐름에 집중한다. 익숙한 한국어 단계 이름과 화살표의 조건을 사용하고 실패 경로를 구분한다.

```text
입력 수신 → 입력 검증
  ├─ 실패 → 오류 반환·기존 상태 보존
  └─ 유효 → 계산·결과 검사
              ├─ 실패 → 오류 반환·기존 상태 보존
              └─ 유효 → 저장·교체
                          ├─ 실패·롤백 → 오류 반환·기존 상태 보존
                          └─ 성공 → 조회·내보내기
```

| 현재 단계 | 조건·행동 | 다음 단계·결과 | 쓰기·보존할 상태 |
| --- | --- | --- | --- |
| 입력 검증 | 유효 / 실패 | 계산·결과 검사 / 오류 반환 | 아직 쓰지 않음, 기존 상태 유지 |
| 계산·결과 검사 | 유효 / 실패 | 저장·교체 / 오류 반환 | 아직 공개하지 않음, 기존 상태 유지 |
| 저장·교체 | 성공 / 실패 | 조회·내보내기 / 오류 반환 | 성공 시 새 결과 공개, 실패 시 기존 상태 보존 |
| 오류 반환 | 원인 안내 | 종료 또는 요구에 따른 수정·재시도 | 실제 복구 정책에 따름 |

이 예시는 저장 전체가 성공해야 조회 결과를 교체하는 설계다. 실패 시 이전 결과를 유지하는 요구와 저장 방식이 실제로 있을 때만 사용한다. 새 데이터 저장과 결과 생성이 분리된 과제라면 각각의 저장 경계를 구분한다.

## PNG 생성·삽입

- 사용 가능한 로컬 도형·그래프 도구로 상자·화살표·분기 라벨을 그리고 PNG로 내보낸다. 특정 도구 설치를 필수 조건으로 만들지 않는다. 원문을 붙여 넣은 스크린샷을 흐름도 대신 사용하지 않는다.
- 기본 파일은 `docs/artifacts/backend-flow.png`다. 작업명별 폴더를 추가하지 않고, 편집 가능한 생성 원본과 재생성 명령도 같은 폴더에 보관하거나 설계 문서에 연결한다. 기존 경로·파일은 우선한다.
- `docs/PLAN.md`에서는 `artifacts/backend-flow.png`, 같은 폴더의 `backend-design.md`에서는 `backend-flow.png`를 이미지 삽입 경로로 사용한다. 문서의 실제 위치에 맞게 계산하고, 생성되지 않은 파일은 이미지 링크로 만들지 않는다.
- PNG 생성이 불가능하면 원인과 미생성 상태를 밝히고 텍스트 흐름도·단계 표를 완성한다. 이미지 생성만 기다리며 독립적인 설계·구현을 멈추지 않는다. 사용자 지정 형식·이미지 생략 요청을 우선한다.

## 추가 그림을 고르는 기준

| 이해하기 어려운 부분 | 필요한 표현 | 보여줄 것 |
| --- | --- | --- |
| 엔터티 간 연결·소유 관계 | PNG 관계도 + 텍스트 관계 + 관계 표 | 실제 키·참조·1:1/1:N/선택 관계 |
| 결과의 유효성·반영 시점 | PNG 상태도 + 텍스트 전이 + 상태 표 | 현재 상태·전이 조건·실패 시 남는 상태 |
| 로그인 뒤 조회·권한 검사·저장 호출 | PNG 순서도 + 텍스트 호출 순서 + 단계 표 | 실제 주체·요청·응답·실패 분기 |

예를 들어 `직원 1 → 배정 0..N ← 1 계획`은 배정 한 건이 직원 한 명과 계획 한 개를 참조한다는 뜻이다. 관계만으로 중복 배정이 방지된다고 판단하지 않으며 유일성·제외 규칙은 요구에서 확인한다. 모든 과제에 모든 보조 그림을 만들지 않는다.

## 확인과 변경

- 단계·필드·권한·저장 시점·분기 조건·실패 보존이 PNG·텍스트·표 및 관련 요구와 같은지 대조한다. 없는 승인 절차·서비스·이력 기능을 그림 때문에 추가하지 않는다.
- PNG를 실제 열어 한글 글리프, 글자 크기, 화살표 방향, 선 교차, 라벨·상자 잘림을 확인한다. PNG 생성·이미지 열람·사용자 Markdown 미리보기·기능 실행 검증을 구분해 보고하며 확인하지 않은 것을 성공으로 표시하지 않는다.
- 설계 판단의 원본은 현재 문서의 텍스트·표다. PNG와 그 생성 원본은 해당 판단을 표현하는 자료이며 별도 설계 원본으로 병행 관리하지 않는다. 변경 시 함께 갱신하고 PNG를 재생성하지 못하면 `재생성 필요`로 표시한다.
