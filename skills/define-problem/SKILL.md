# 문제 정의

주어진 현상에서 출발해 누구의 어떤 불편·손실·목표와의 차이를 해결할지 명확히 한다. 한국어를 기본으로 하며 사용자가 지정한 언어와 형식을 따른다.

## 판단 기준

- 현상, 영향, 원인, 해결책을 구분한다. “예약이 겹쳤다”는 관찰이고, “접수 경로가 분리돼서 그렇다”는 근거 확인이 필요한 원인 가설이다. “통합 시스템이 없다”는 표현만으로 문제나 원인을 확정하지 않는다.
- 제공 자료와 기존 대화를 먼저 사용한다. 관찰된 사실에는 가능한 범위에서 파일·문단·행·날짜 등 확인 가능한 근거를 연결한다. 사용자의 설명은 사용자 진술로, 해석과 원인 추정은 가설로 표시한다.
- 원인이 아직 불명확해도 영향을 근거로 문제를 정의할 수 있다. 근본 원인을 찾았다고 단정하거나 원인이 하나라고 가정하지 않는다. 원인 검토가 필요하면 지지·반박 근거와 가설을 구분할 추가 확인 방법을 제시한다.
- 대상, 발생 맥락·기간, 현재 상태, 원하는 상태, 영향, 범위 중 판단에 필요한 내용을 정리한다. 규모·빈도·기준값이 없으면 미확인으로 남긴다. 목표 수치를 제안한다면 확인된 요구와 구분한다.
- 사용자가 정한 목적·범위·해결책 제약을 존중한다. 그 선택의 문제점을 발견하면 근거와 영향을 설명하되 과제를 임의로 바꾸지 않는다. 새로운 해결책 선정이나 구현은 요청 범위에 포함된 경우에 진행한다.

## 안티패턴과 예방 지침

- **단일 사례의 일반화:** 한 사례가 보여주는 범위까지만 문제를 진술하고, 반복성·대표성은 별도로 확인한다. 다만 한 번의 사건도 영향이 크면 그 자체로 문제일 수 있으므로, 사례 수가 적다는 이유만으로 중요성을 낮추지 않는다.
- **특정 지점이나 가설에 고정:** 특정 원인을 핵심 문제로 좁히기 전에 같은 현상을 설명할 다른 가능성과 현재 가설에 맞지 않는 근거가 있는지 확인한다. 가능성을 확인한 것과 대안을 배제할 증거를 확보한 것을 구분한다. 근거 없는 원인 후보를 정해진 개수만큼 만들어 내거나 모든 가능성을 조사할 필요는 없다.
- **그럴듯한 설명에서 검토 종료:** 원인이나 범위가 불확실한 경우, 어떤 추가 관찰·증거가 나오면 현재 문제 정의를 수정해야 하는지 적는다. 확인할 수 없는 부분은 잠정으로 남기고, 현재 근거로 진행할 수 있는 판단과 추가 확인이 필요한 판단을 구분한다.

## 이미 실행 중인 과제

새 증거가 대상·범위·원인 가설을 바꿀 때만 해당 판단으로 돌아간다. 구현 세부 질문·결함·표현 수정 때문에 전체 문제 정의를 재시작하지 않는다. 기존 기능의 오류 수정인지 새 업무 문제인지 먼저 구분하고 관련 근거만 보완한다.

## 정보가 부족할 때

먼저 가능한 범위의 문제 진술을 작성한다. 문제의 대상이나 방향을 바꿀 핵심 누락·충돌만 질문하고, 답이 없어도 정리할 수 있는 내용은 진행한다. 근거가 없는 가설을 필수 조건처럼 쓰거나, 모든 항목을 채우기 위해 질문을 늘리지 않는다.

## 원인에서 개입 지점으로 연결

- **Problem Space:** 누구의 어느 업무 구간인지, 시작·완료·관련 역할과 범위를 정한다.
- **Pain:** 그 구간에서 어떤 행동·판단이 막히며 어떤 부담이 생기는지 사례와 연결한다. 빈도·시간·영향은 근거가 있는 범위만 쓴다.
- **Mechanism:** `사건·조건 → 행동·인계 → 중간 결과 → Pain`으로 발생 과정을 설명한다. 각 연결에 근거 또는 추정을 표시한다. “정보 분산”, “책임 불명확” 같은 이름만으로 원인을 입증했다고 하지 않는다. 다른 설명과 반례를 함께 남긴다.
- **Opportunity:** 어떤 역할의 어느 행동·시점·책임·구조를 현재 상태에서 어떤 상태로 바꾸면 Pain을 줄일 수 있는지 후보로 정리한다. 원인 가설과 연결하고, 개입 가능성·예상 부담·기대 변화·판단을 바꿀 증거로 후보의 우선순위를 검토한다. 숫자나 후보 개수를 억지로 채우지 않는다.

예를 들어 “상태 변화가 공용 기록에 늦게 반영되어 재문의한다”는 Mechanism 가설에 대해, “최초로 상태를 아는 사람과 다음 행동을 결정하는 사람 사이의 갱신·전달 지점 개선”은 Opportunity 후보다. “상태 알림 봇 구축”은 그 지점에 적용할 Solution 후보이므로 여기에서 확정하지 않는다. “최신 정보를 확인할 수 있어야 함”은 요구사항으로 이어질 결과 조건이다.

원인이 미확정이면 Opportunity도 잠정 가설로 남기고 작은 실험에서 확인할 항목을 전달한다. 원인 입증이 끝나야만 진행하도록 막거나, 이미 선택된 해결책을 다시 선정하지 않는다. 개입 탐색이 범위 밖이면 이유를 적고 해당 부분은 생략한다.

## 결과

단계 결과는 아래 Markdown 출력 규약에 맞추고, 내용의 깊이와 표의 행 수는 문제의 복잡도에 맞춘다.

- **문제 진술:** 누가, 어떤 상황에서, 어떤 어려움이나 목표와의 차이를 겪으며, 어떤 영향이 있는가.
- **근거와 원인 상태:** 확인된 사실, 해석·원인 가설, 아직 모르는 것. 근거가 충돌하면 충돌 자체를 남긴다.
- **목표와 범위:** 어떤 상태가 되면 문제가 개선됐다고 볼 수 있는가. 주어진 범위와 제외 사항을 보존한다.
- **다음 확인:** 문제 정의를 바꿀 수 있는 핵심 질문이나 추가 증거. 확인되지 않은 원인에 의존하는 결정은 잠정으로 표시한다.
- **개입 지점 후보:** 원인과 연결된 역할·업무 지점·현재 행동·바꿀 방향·기대 변화 및 남은 가정. 원인이 잠정이면 그 상태를 유지한다.

요구사항 정리로 넘길 때는 문제 진술, 근거, 원인의 발생 과정, 개입 지점 후보, 원하는 결과, 확정된 제약, 미해결 질문을 전달한다. 원인·개입 가설은 다음 단계에 전달됐다는 이유로 사실이나 확정 선택으로 승격하지 않는다.

## 입력과 Markdown 출력

- **입력:** 01-discovery.md의 E/C-ID·업무 범위·Pain·추가 질문, 또는 직접 제공된 요청·원자료. 사용한 근거를 확인할 수 있으면 앞 단계 파일 없이 시작한다.
- **출력:** 기준 문서의 문제·선택 근거 절 또는 단독 `02-problem-definition.md`. P-xx 문제·Pain, M-xx 발생 과정과 반례, O-xx 개입 지점 후보, 원하는 결과·제약·미해결 질문을 clarify-requirements와 evaluate-solutions에 전달한다.
- [출력 양식](assets/output-template.md)을 읽고 이번 판단에 필요한 항목을 사용한다. 사용자 지정 형식과 기존 관리 위치를 우선한다. 여러 단계를 통합 관리하는 과제는 기준 문서(기본 `docs/PLAN.md`)의 **문제·선택 근거** 절을 갱신하고 별도 `02-problem-definition.md`를 중복 생성하지 않는다.
- 단독 실행이거나 상세 분리가 필요한 경우에만 지정 경로 또는 `docs/artifacts/02-problem-definition.md`에 작성한다. 작업명별 하위 폴더는 만들지 않는다. 다른 산출물과 파일명이 겹칠 때만 파일명에 대상을 붙여 구분한다. 단독 사용을 위해 PLAN이나 다른 스킬을 요구하지 않는다. 긴 원자료·실행 증거는 링크로 연결하고 현재 판단의 원본을 한 곳으로 유지한다. 쓰기가 불가능하거나 사용자가 파일 생성을 원하지 않으면 대화에 제공하고 미저장을 알린다. 스킬 설치 폴더에 결과를 저장하지 않는다.
- 입력·원자료를 실제로 읽고 출처·사용 버전·기존 ID를 유지한다. 앞 단계 파일 없이 직접 자료로 시작할 수 있다. 모르는 값·가설·AI 제안은 그대로 표시하고 없는 상위 문서를 참조하지 않는다.
- 의미 있는 변경은 리비전·이유·영향 ID를 남긴다. 최초 판단·사용자 설명은 이력에 보존하고 현재 요약은 최신 판단으로 갱신한다. 입력 변경 시 영향 항목을 재검토하며, 확인 전에는 `재검토 필요`로 표시한다. 수행하지 않은 후속 검사를 갱신했다고 하지 않는다.
- 사용자 검토는 실제 피드백 전까지 `미검토`다. 문서 작성·AI 검사·사용자 검토·선택/위임을 구분하고 근거를 남긴다. 결과의 핵심·미확인·다음 행동을 보여주되 이미 허용된 후속 작업에 재승인을 요구하지 않는다.
- 짧은 문답은 현재 원본에 반영한다. 수행하지 않은 단계·빈 양식을 만들지 않으며 해당 없는 절은 생략할 수 있다. 생략 이유가 범위 판단에 영향을 주면 짧게 적는다.
- 보강 시 기존 목차와 상하위 관계를 읽고 관련 절·문단·표를 직접 수정한다. 문서 끝에 별도 보강 절을 누적하지 않으며, 새 절은 기존 항목으로 담을 수 없을 때만 적절한 제목 수준에 추가한다. 중복·대체된 설명을 정리하고 영향받는 상위 요약·하위 근거·연관 항목의 모순과 제목·번호·링크를 확인하되 기존 ID·원자료·이전 결정은 보존한다.
