# 요구사항 정리

해결할 문제를 검증 가능한 조건으로 연결한다. 문서·분석·업무 절차·소프트웨어 등 과제의 실제 산출물에 맞춰 정리한다. 한국어를 기본으로 하며 사용자가 지정한 언어와 형식을 따른다.

## 범위와 근거

- 기존 문제 정의가 있으면 활용한다. 별도 문제 정의 문서가 없어도 과제에서 목적이 명확하면 바로 정리한다. 목적이 불명확한 부분은 잠정으로 표시하고 결과를 바꿀 핵심 질문만 한다.
- 문제·개입 지점 ID가 있으면 각 요구가 어느 문제와 기대 변화에 대응하는지 연결한다. Opportunity는 바꿀 역할·업무 지점·행동의 후보이며, 요구사항은 달성할 결과와 지켜야 할 조건이다. 둘을 같은 항목으로 합치거나 잠정 개입 가설을 필수 구현 방식으로 바꾸지 않는다. 연결할 정보가 없으면 이유를 남기고 제공된 요청에서 요구를 도출한다.
- 솔루션 선택 전에는 달성할 결과, 업무 규칙, 입력·출력, 제약과 성공 기준을 정리한다. 특정 앱·모델·기술을 임의로 필수 조건에 넣지 않는다. 사용자가 이미 선택한 방식·도구·제출 형식은 제약으로 보존한다.
- 각 요구의 출처와 상태를 구분한다. 명시된 요구, 그 요구를 충족하는 데 필요한 해석, AI의 개선 제안, 미확정 사항을 섞지 않는다. 사용자의 명시적 조건만으로 충분한 부분은 재승인을 요구하지 않는다.
- 우선순위나 필수 여부가 주어졌으면 보존한다. 서로 충돌하는 조건은 적용 대상과 출처를 확인하고, 원문에 우선순위가 없으면 임의로 선택하지 않는다. 충돌에 의존하지 않는 요구는 계속 정리한다.

## 요구사항을 구체화하는 기준

- 하나의 요구가 무엇을 충족해야 하는지 확인할 수 있도록 쓴다. 필요한 경우 주체, 조건, 동작·결과, 예외를 명시한다. “정확하게”, “빠르게”, “편리하게” 같은 표현은 확인할 지표나 관찰 가능한 결과로 풀되 목표값을 만들어 확정하지 않는다.
- 계산·분석에서는 대상·기간·단위·분모·합계·자료 간 연결과 출력 형식을 확인한다. 처리 도구에서는 입력·출력, 순서, 경계·예외와 실패 시 동작 등 결과를 바꾸는 조건을 확인한다. 해당 과제에 필요한 항목만 사용한다.
- 검증 기준은 요구사항에서 도출한다. 확인 방법과 기대되는 결과를 연결하고, 필요한 기준값이나 자료가 없으면 무엇이 더 필요한지 적는다. 성공 기준을 새로 제안하는 경우 제안임을 표시한다.
- 데이터·판정 과제는 **개별 정확성**과 **전체 정합성**을 나눈다. 개별 사례는 원자료 위치·값, 적용 규칙·우선순위, 기대 판단을 연결한다. 전체 자료는 관련 있는 행 수·순서·누락·중복·연결 키·분모·합산 범위를 확인할 조건을 정한다. 합계 일치만으로 개별 판단의 정확성을 대신하지 않는다.
- 기대값은 원자료와 규칙에서 도출할 수 있어야 한다. 구현 결과를 복사해 기대값으로 쓰지 않는다. 대표 사례 수는 판단 조건과 위험에 맞추며, 표본 몇 건의 통과를 전체 정확성의 완료 조건으로 확대하지 않는다.
- **산출물 완료 조건**과 **업무 효과 확인 조건**을 구분한다. 알림이 정해진 대상·시점에 도착하는지와 문의·전체 업무 부담이 줄었는지는 다른 조건이다. 효과를 확인할 기준값·자료가 없으면 필요한 측정과 미확인을 남긴다. 구현이나 현장 시범 운영이 요청 범위 밖이면 이를 새 필수 제출물로 추가하지 않는다.
- 반복된 요구는 통합하되 각 출처와 예외를 보존한다. 상충하는 요구를 문구만 합쳐 모순이 사라진 것처럼 처리하지 않는다.

## 정리를 끝내고 실행으로 넘길 때

- 원문·첨부 규격·데이터 설명의 필수 동작과 제출물을 한 번 대조해 누락을 확인한다. 이후에는 새 요구, 표현 수정, 구현 결정을 구분하고 영향받는 부분만 보완한다.
- 미결정은 **착수 차단 / 구현 중 결정 / 후속 후보**로 나누고 관련 R-ID·결정 시점·지금 가능한 범위를 적는다. 데이터 의미·권한·필수 출력이 달라지는 충돌은 차단일 수 있지만, 위임된 기술 선택이나 선택 기능의 미채택이 전체 착수를 막지는 않는다.
- 첫 흐름의 필수 동작·핵심 예외·독립 기대 결과와 차단 결정 처리 방법이 정리되면 요구 검토를 마친다. 구현 요청이 있으면 가능한 범위의 최소 설계·구현으로 이어간다. 모든 문장·정책 제안값 확정을 기다리지 않는다.
- 반복 사용 서비스는 생성 이후 입력 변경·재생성·재접속 시 기대 동작, 기존 결과를 언제 바꾸며 실패 시 무엇을 보존할지도 관련 요구에 포함한다. 필요가 확인되지 않은 이력·공지·승인 기능을 자동 필수화하지 않는다.

## 결과

먼저 목적·대상·범위를 짧게 요약하고, 아래 Markdown 출력 규약과 [출력 양식](assets/output-template.md)으로 결과를 저장한다. 요구사항 표에는 R-ID, 연결 P/O-ID, 조건·예외·우선순위, 출처, 상태·필수 여부, 검증 방법·기대 결과를 남긴다. 표의 항목은 출력 양식에서 필요한 것을 사용하며, 요구의 개수와 설명의 깊이는 과제에 맞춘다.

이어 핵심 충돌·미확정 질문과 그로 인해 결정할 수 없는 부분을 적는다. 범위를 넘어선 개선 제안이 필요하면 요구사항과 별도로 표시한다. 검증 방법을 작성한 것을 실제 검증 완료로 표현하지 않는다.

예를 들어 “같은 전시실의 승인 예약은 시간이 겹치지 않아야 한다”는 해결책의 충족 조건이다. 접수 순서, 맞닿는 시각의 처리, 충돌 시 출력은 자료에서 확인하거나 미확정으로 남긴다. CSV나 웹 화면을 만들라는 조건이 없다면 특정 구현 형태를 필수 요구로 추가하지 않는다.

“각 행에 판정·사유가 있다”는 존재 여부만 확인한다. 정확성이 요구되면 “입력 행 수·순서를 보존하고, 각 판정·사유가 원문 규칙과 우선순위에 따른 기대값과 일치한다”처럼 구체화한다. 실제 대조 단계에는 요구 ID, 기준·출처, 사례별 기대 판단, 미확정 사항을 전달한다. 이 스킬에서 기준을 설계한 것과 이후 산출물을 실제로 검사한 것을 구분한다.

마지막으로 요구사항을 원문과 대조해 누락·추가·충돌을 확인한다. 문제 정의의 가설을 확정 요구로 옮기지 않았는지, 각 핵심 요구의 충족 여부를 어떤 증거로 판단할 수 있는지 점검한다.

## 입력과 Markdown 출력

- **입력:** 02-problem-definition.md의 P/M/O-ID·원하는 결과·제약, 관련 E-ID·규정·담당자 응답. 이미 선택된 방식이 있으면 그 결정을 입력 제약으로 보존한다.
- **출력:** 기준 문서의 요구와 완료 기준·미결정 절 또는 단독 `03-requirements.md`. R-xx 요구, 연결된 P/O-ID, 출처·상태·필수 여부, 기대 판단과 검증 방법, 충돌·미확정을 evaluate-solutions 및 verify-work-results에 전달한다.
- [출력 양식](assets/output-template.md)을 읽고 이번 판단에 필요한 항목을 사용한다. 사용자 지정 형식과 기존 관리 위치를 우선한다. 여러 단계를 통합 관리하는 과제는 기준 문서(기본 `docs/PLAN.md`)의 **요구와 완료 기준·미결정** 절을 갱신하고 별도 `03-requirements.md`를 중복 생성하지 않는다.
- 단독 실행이거나 상세 분리가 필요한 경우에만 지정 경로 또는 `docs/artifacts/03-requirements.md`에 작성한다. 작업명별 하위 폴더는 만들지 않는다. 다른 산출물과 파일명이 겹칠 때만 파일명에 대상을 붙여 구분한다. 단독 사용을 위해 PLAN이나 다른 스킬을 요구하지 않는다. 긴 원자료·실행 증거는 링크로 연결하고 현재 판단의 원본을 한 곳으로 유지한다. 쓰기가 불가능하거나 사용자가 파일 생성을 원하지 않으면 대화에 제공하고 미저장을 알린다. 스킬 설치 폴더에 결과를 저장하지 않는다.
- 입력·원자료를 실제로 읽고 출처·사용 버전·기존 ID를 유지한다. 앞 단계 파일 없이 직접 자료로 시작할 수 있다. 모르는 값·가설·AI 제안은 그대로 표시하고 없는 상위 문서를 참조하지 않는다.
- 의미 있는 변경은 리비전·이유·영향 ID를 남긴다. 최초 판단·사용자 설명은 이력에 보존하고 현재 요약은 최신 판단으로 갱신한다. 입력 변경 시 영향 항목을 재검토하며, 확인 전에는 `재검토 필요`로 표시한다. 수행하지 않은 후속 검사를 갱신했다고 하지 않는다.
- 사용자 검토는 실제 피드백 전까지 `미검토`다. 문서 작성·AI 검사·사용자 검토·선택/위임을 구분하고 근거를 남긴다. 결과의 핵심·미확인·다음 행동을 보여주되 이미 허용된 후속 작업에 재승인을 요구하지 않는다.
- 짧은 문답은 현재 원본에 반영한다. 수행하지 않은 단계·빈 양식을 만들지 않으며 해당 없는 절은 생략할 수 있다. 생략 이유가 범위 판단에 영향을 주면 짧게 적는다.
- 보강 시 기존 목차와 상하위 관계를 읽고 관련 절·문단·표를 직접 수정한다. 문서 끝에 별도 보강 절을 누적하지 않으며, 새 절은 기존 항목으로 담을 수 없을 때만 적절한 제목 수준에 추가한다. 중복·대체된 설명을 정리하고 영향받는 상위 요약·하위 근거·연관 항목의 모순과 제목·번호·링크를 확인하되 기존 ID·원자료·이전 결정은 보존한다.
