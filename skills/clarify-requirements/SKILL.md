# 요구사항 정리

해결할 문제를 검증 가능한 조건으로 연결한다. 문서·분석·업무 절차·소프트웨어 등 과제의 실제 산출물에 맞춰 정리한다. 한국어를 기본으로 하며 사용자가 지정한 언어와 형식을 따른다.

## 범위와 근거

- 기존 문제 정의가 있으면 활용한다. 별도 문제 정의 문서가 없어도 과제에서 목적이 명확하면 바로 정리한다. 목적이 불명확한 부분은 잠정으로 표시하고 결과를 바꿀 핵심 질문만 한다.
- 솔루션 선택 전에는 달성할 결과, 업무 규칙, 입력·출력, 제약과 성공 기준을 정리한다. 특정 앱·모델·기술을 임의로 필수 조건에 넣지 않는다. 사용자가 이미 선택한 방식·도구·제출 형식은 제약으로 보존한다.
- 각 요구의 출처와 상태를 구분한다. 명시된 요구, 그 요구를 충족하는 데 필요한 해석, AI의 개선 제안, 미확정 사항을 섞지 않는다. 사용자의 명시적 조건만으로 충분한 부분은 재승인을 요구하지 않는다.
- 우선순위나 필수 여부가 주어졌으면 보존한다. 서로 충돌하는 조건은 적용 대상과 출처를 확인하고, 원문에 우선순위가 없으면 임의로 선택하지 않는다. 충돌에 의존하지 않는 요구는 계속 정리한다.

## 요구사항을 구체화하는 기준

- 하나의 요구가 무엇을 충족해야 하는지 확인할 수 있도록 쓴다. 필요한 경우 주체, 조건, 동작·결과, 예외를 명시한다. “정확하게”, “빠르게”, “편리하게” 같은 표현은 확인할 지표나 관찰 가능한 결과로 풀되 목표값을 만들어 확정하지 않는다.
- 계산·분석에서는 대상·기간·단위·분모·합계·자료 간 연결과 출력 형식을 확인한다. 처리 도구에서는 입력·출력, 순서, 경계·예외와 실패 시 동작 등 결과를 바꾸는 조건을 확인한다. 해당 과제에 필요한 항목만 사용한다.
- 검증 기준은 요구사항에서 도출한다. 확인 방법과 기대되는 결과를 연결하고, 필요한 기준값이나 자료가 없으면 무엇이 더 필요한지 적는다. 성공 기준을 새로 제안하는 경우 제안임을 표시한다.
- 데이터·판정 과제는 **개별 정확성**과 **전체 정합성**을 나눈다. 개별 사례는 원자료 위치·값, 적용 규칙·우선순위, 기대 판단을 연결한다. 전체 자료는 관련 있는 행 수·순서·누락·중복·연결 키·분모·합산 범위를 확인할 조건을 정한다. 합계 일치만으로 개별 판단의 정확성을 대신하지 않는다.
- 기대값은 원자료와 규칙에서 도출할 수 있어야 한다. 구현 결과를 복사해 기대값으로 쓰지 않는다. 대표 사례 수는 판단 조건과 위험에 맞추며, 표본 몇 건의 통과를 전체 정확성의 완료 조건으로 확대하지 않는다.
- **산출물 완료 조건**과 **업무 효과 확인 조건**을 구분한다. 알림이 정해진 대상·시점에 도착하는지와 문의·전체 업무 부담이 줄었는지는 다른 조건이다. 효과를 확인할 기준값·자료가 없으면 필요한 측정과 미확인을 남긴다. 구현이나 현장 시범 운영이 요청 범위 밖이면 이를 새 필수 제출물로 추가하지 않는다.
- 반복된 요구는 통합하되 각 출처와 예외를 보존한다. 상충하는 요구를 문구만 합쳐 모순이 사라진 것처럼 처리하지 않는다.

## 결과

먼저 목적·대상·범위를 짧게 요약한다. 요구가 여러 개면 다음 열을 참고해 표로 정리한다. 작은 요청에는 간결한 목록을 사용한다.

| 요구 ID | 충족할 조건 | 출처·근거 | 상태 | 검증 방법·기대 결과 |
| --- | --- | --- | --- | --- |

이어 핵심 충돌·미확정 질문과 그로 인해 결정할 수 없는 부분을 적는다. 범위를 넘어선 개선 제안이 필요하면 요구사항과 별도로 표시한다. 검증 방법을 작성한 것을 실제 검증 완료로 표현하지 않는다.

예를 들어 “같은 전시실의 승인 예약은 시간이 겹치지 않아야 한다”는 해결책의 충족 조건이다. 접수 순서, 맞닿는 시각의 처리, 충돌 시 출력은 자료에서 확인하거나 미확정으로 남긴다. CSV나 웹 화면을 만들라는 조건이 없다면 특정 구현 형태를 필수 요구로 추가하지 않는다.

“각 행에 판정·사유가 있다”는 존재 여부만 확인한다. 정확성이 요구되면 “입력 행 수·순서를 보존하고, 각 판정·사유가 원문 규칙과 우선순위에 따른 기대값과 일치한다”처럼 구체화한다. 실제 대조 단계에는 요구 ID, 기준·출처, 사례별 기대 판단, 미확정 사항을 전달한다. 이 스킬에서 기준을 설계한 것과 이후 산출물을 실제로 검사한 것을 구분한다.

마지막으로 요구사항을 원문과 대조해 누락·추가·충돌을 확인한다. 문제 정의의 가설을 확정 요구로 옮기지 않았는지, 각 핵심 요구의 충족 여부를 어떤 증거로 판단할 수 있는지 점검한다.
