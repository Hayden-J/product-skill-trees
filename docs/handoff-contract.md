# 스킬 간 근거·결정 전달 규약

스킬의 사용 시점·흐름·입출력은 [스킬맵](skill-map.md)에서 관리한다. 이 문서는 저장·참조·갱신 원칙을 다룬다. 과제 원문·사용자 지정 형식과 기존 관리 위치를 우선한다.

## 저장 방식

- 여러 단계의 결과를 관리할 때 기본은 **현재 기준 문서의 관련 절 갱신**이다. 기본 경로는 `docs/PLAN.md`지만 지정 문서가 역할을 맡을 수 있다.
- 단독 실행·큰 상세 분석·별도 제출 의무가 있을 때만 단계 파일을 만든다. 기본 경로는 `artifacts/<작업명>/`이며 기존 파일은 이어 쓴다. 스킬 출력 양식의 필요한 항목을 사용하고 해당 없는 절은 생략할 수 있다.
- 앞 단계 파일은 필수 의존성이 아니다. 실제 원문·대화·직접 자료로 시작하고 수행하지 않은 단계·합의·ID를 만들어 참조하지 않는다.
- 현재 판단의 원본은 내용별로 한 곳만 정한다. 별도 상세 원본이 있으면 기준 문서는 핵심 설명과 링크만 유지한다. [문서 역할·제출본 관리](development-handoff.md)를 따른다.
- 쓰기가 불가능하거나 사용자가 파일 생성을 원하지 않으면 같은 내용을 대화에 제공하고 미저장을 알린다. 결과를 스킬 설치 폴더에 저장하지 않는다.

보강 시에는 [공통 문서 위계 규칙](../templates/AGENTS.template.md#보강수정-시-문서-위계-유지)에 따라 현재 원본의 관련 항목을 수정하고, 기준 문서의 요약·링크와 영향받는 항목을 갱신한다. 예를 들어 로그인 실패 처리를 보강하면 기존 인증 설계의 실패 처리 항목과 관련 검증 기준을 고친다. 상세 원본이 분리돼 있으면 PLAN에는 핵심 변경과 해당 원본 링크를 반영하고, 변경 이유는 Worklog 또는 기존 변경 이력에 남긴다.

## 근거와 상태

결과에는 이번 판단에 필요한 결론·미확인·출처·입력 버전·항목 ID·실제 선택 근거·다음 행동을 남긴다. 사용자 검토는 실제 피드백 전까지 `미검토`다. 문서 작성, AI 검사, 사용자 검토, 선택/위임, 구현·운영 효과는 서로 다르다.

Problem Space는 업무 범위, Pain은 막힌 행동·부담, Mechanism은 발생 과정, Opportunity는 바꿀 지점, Solution은 구체 방법이다. 원인·개입 가설이 요구·계획으로 전달됐다는 이유로 사실이나 필수 구현으로 바뀌지 않는다. “정보가 오래됐다”는 진술만으로 갱신이 늦어진 원인을 확정하지 않는다.

실험 계획·설계 그림·테스트 계획은 실행 증거가 아니다. 계산·관찰·실제 실행 주체를 표시하며 AI 수행을 사용자 직접 경험으로 기록하지 않는다. 시험·가상 과제의 응답은 과제 내 근거로 다룬다.

## ID·버전 유지

- E 근거, C 사례, P 문제, M 발생 과정, O 개입 지점, R 요구, S 대안, X 실험 계획, V 검증을 필요한 만큼 쓴다. 실제 결정·위임·변경은 Worklog의 D-ID에 연결한다. 구현 단위를 나눌 때만 U-ID·부모 S-ID를 쓴다.
- 기존 ID를 유지하고 새 항목만 추가한다. 같은 ID가 여러 문서에 있으면 `경로 + ID`로 구분한다. 통합 문서에서 새 ID를 만들 때는 문서 내 기존 ID와 충돌하지 않게 한다.
- 입력은 실제 링크·리비전·항목 위치로 연결한다. 원자료에 리비전이 없으면 날짜·행·대화 턴 등 실제 식별 정보를 쓴다. 미생성 파일명은 경로 설명으로 남기되 존재하는 링크처럼 표시하지 않는다.
- 관련 입력을 실제로 다시 읽고 영향받는 판단을 확인한다. 요약을 읽은 것을 원문 대조라고 하지 않는다. 입력 변경 후 확인 전에는 `재검토 필요`다.
- 변경 이유·최초 판단은 Worklog 또는 해당 원본의 변경 이력에 보존하고 현재 요약은 최신화한다. 같은 이력을 여러 문서에 복사하지 않는다. 재수행하지 않은 후속 결과는 갱신 완료로 표시하지 않는다.

## 판단이 다음 행동으로 이어지는 조건

- 요구 정리는 필수 동작·핵심 기대값·차단 결정 처리 방법이 정리되면 마친다. 미결정은 착수 차단/구현 중 결정/후속 후보로 나눈다.
- 선택은 사용자 선택 또는 실제 위임 범위와 근거를 남긴다. 미선택 대안을 실행 목록으로 바꾸지 않으며 이미 위임된 작업에 추가 승인을 요구하지 않는다.
- 백엔드 설계는 첫 흐름의 데이터·책임·저장·권한·변경/실패 조건을 Mermaid와 해설로 전달한다. 모든 상세 설계 완료를 구현 전제조건으로 삼지 않는다.
- 검증은 원자료·기준 → 독립 기대값 → 실제 결과·증거 → 판정·한계로 연결한다. 문서/모듈/통합/실제 환경을 구분한다.

실제 협업·결정·작업 결과 기록은 [공통 AGENTS](../templates/AGENTS.template.md#worklog-자동-기록)와 [Worklog 양식](../templates/WORKLOG.template.md)을 따른다. 셋업이 백그라운드에서 대화를 수집하는 기능은 없다.

이 저장소의 `artifacts/`는 Git에서 제외되지만 셋업은 과제 폴더의 `.gitignore`를 바꾸지 않는다. 제출·공유는 과제 조건과 실제 요청 범위를 따른다.
