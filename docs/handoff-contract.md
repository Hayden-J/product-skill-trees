# 스킬 간 입력·출력과 Markdown 검토 규약

스킬 이름은 작업을 나누고, Problem Space → Pain → Mechanism → Opportunity → Solution은 판단의 내용을 나눈다. 둘은 일대일 관계가 아니다. 인터뷰에서 근거를 모으고, 문제 정의에서 원인과 개입 지점을 연결하고, 요구사항으로 결과 조건을 정한 뒤 해결안을 비교한다. 검증은 어느 단계에서도 수행할 수 있다.

## 입력과 출력 연결

| 스킬 | 입력 | 출력 MD | 다음 단계가 읽는 내용 |
| --- | --- | --- | --- |
| discovery-interview | 과제·실제 응답·업무자료 | `01-discovery.md` | E-ID 근거, C-ID 사례, 업무 범위·Pain·원인·개입 탐색 단서 |
| define-problem | 인터뷰 기록 또는 직접 자료 | `02-problem-definition.md` | P-ID 문제·Pain, M-ID 발생 과정, O-ID 개입 지점, 근거·가정·범위 |
| clarify-requirements | 문제·개입 지점·규정·사용자 결정 | `03-requirements.md` | R-ID 조건과 P/O 연결, 출처·필수 여부·검증 기준·충돌 |
| evaluate-solutions | P/M/O-ID, R-ID, 우선순위·제약 | `04-solution-evaluation.md` | S-ID 대안과 연결, 추천/실제 선택, X-ID 실험 계획·판단 변경 조건 |
| verify-work-results | 검토 대상 단계 문서·산출물·원자료·기준·실행 증거 | `05-verification.md` | V-ID 실제 대조, 결과·확인 범위·불일치, 돌아갈 문서·항목 |

앞 단계 파일은 필수 의존성이 아니다. 원문과 대화로 충분하면 해당 자료를 입력표에 적고 필요한 단계부터 시작한다. 문제 발굴만 진행한 경우에는 01 → 02 → 05를 사용하며 03·04를 만들지 않는다. 기존 해결책이 확정된 구현 요청에서는 문제 정의나 대안 선정부터 다시 시작하지 않는다.

## 최종 업무 계획과 협업 기록으로 연결

해결안이 선택되고 계획·구현까지 요청되면 실제 단계 산출물과 과제 원문을 [PLAN 양식](../templates/PLAN.template.md)에 종합한다. 기본 경로는 `docs/PLAN.md`다. 앞 단계를 모두 수행하도록 강제하지 않으며, 직접 자료로 시작한 경우 그 자료와 실제 결정을 근거로 쓴다. 기존 05가 있으면 검증된 결과·한계를 반영하지만, 개발 전 05 작성이 필수 조건은 아니다.

PLAN에는 목표·타겟 사용자·사용자가 겪는 문제·이번 문제·요구사항·선택한 솔루션·제외 범위·솔루션 단위 우선순위·단계별 산출물과 검증 방법을 본문으로 풀어 쓴다. 입력 링크·리비전·E/C/P/M/O/R/S/X/V-ID를 유지하고, 실제 선택·위임·변경은 `docs/WORKLOG.md`의 D-ID에 연결한다. 선택한 S-ID를 개발 단위로 나눌 때만 U-ID와 부모 S-ID를 함께 사용한다. 미선택 대안을 실행 목록으로 바꾸지 않는다.

에이전트는 별도 요청 없이 [Worklog 다섯 열 양식](../templates/WORKLOG.template.md)에 현재 사용자와의 실제 질문·응답·제안·결정·수행 작업·검증 결과를 응답 종료 전에 남긴다. 변경은 새 D-ID로 기록한 뒤 PLAN의 리비전·영향받는 요구·산출물·검증 방법을 갱신한다. 구현 후 `05-verification.md`는 PLAN의 기준과 실제 실행 증거를 대조한다. 계획·사용자 검토·실제 검증은 별개이며, 미결정은 영향받는 부분에만 표시한다. [개발 착수 절차](development-handoff.md)와 [요청 문구](../PROMPTS.md)를 참고한다.

## 다섯 요소를 구분하는 기준

| 요소 | 남길 내용 | 주된 위치 |
| --- | --- | --- |
| Problem Space | 대상·업무 구간·시작·완료·관계자·범위 | 01, 02 |
| Pain | 막힌 행동·판단·부담·영향과 근거 | 01의 사례, 02의 P-ID |
| Mechanism | 사건·조건 → 행동·인계 → 중간 결과 → Pain, 연결별 근거·반례 | 02의 M-ID |
| Opportunity | 누구의 어느 지점에서 무엇을 바꿀지, 기대 변화·개입 가능성·부담 | 02의 O-ID |
| Solution | O-ID에 적용할 구체적 방법과 비교, R-ID 충족, 작은 시험 | 04의 S/X-ID |

“정보가 오래됐다”는 진술만으로 원인을 확정하지 않는다. 누가 어떤 상태 변화를 언제 알았고 기록·전달이 어디에서 늦어졌는지를 확인한다. “갱신·전달 지점을 개선한다”는 개입 방향과 “알림 봇을 만든다”는 구체적 방법을 구분한다. 원인이 잠정이면 개입 방향과 해결안도 그 가정에 의존한다는 사실을 유지한다.

## 저장과 검토

사용자가 지정한 폴더를 우선한다. 지정이 없으면 현재 프로젝트의 `artifacts/<작업명>/`에 해당 단계 파일을 저장한다. 이 저장소의 `artifacts/`는 Git에서 제외된다. 기본 파일명은 연결을 쉽게 하기 위한 규약이며 사용자 지정 이름·기존 문서가 있으면 그 경로를 유지한다.

모든 단계 출력은 각 스킬의 `assets/output-template.md`를 사용하며 다음 내용을 갖는다.

1. 문서 정보: 작업명, 문서 ID, 작성·갱신일, 리비전, 작업 상태, 사용자 검토 상태.
2. 검토 요약: 핵심 결론, 미확인, 사용자가 확인할 점.
3. 사용한 입력: 실제 링크·사용 버전·항목 ID·근거 종류·사용 목적.
4. 단계별 상세 판단: 사례·문제·원인·개입·요구·대안·검증 중 해당 내용.
5. 사용자 검토: 판단을 확인할 질문과 실제 의견·결정의 근거.
6. 다음 단계에 전달: 대상 단계, 전달 ID·내용, 보존할 가정, 진행 가능한 범위.
7. 변경 기록: 무엇이 왜 바뀌었으며 어떤 후속 판단에 영향을 주는지.

사용자 검토는 기본 **미검토**다. 실제 의견을 받은 경우에만 검토 완료·수정 요청 등으로 바꾸고 근거를 남긴다. 작업이 정리 완료됐거나 검사가 통과했다고 사용자 검토도 완료된 것은 아니다. AI 추천, 사용자 선택, 위임에 따른 선택도 구분한다.

각 단계가 정리될 때 파일 링크와 결론·확인할 점을 보여준다. 이것이 매 단계의 새로운 승인 절차를 뜻하지는 않는다. 사용자가 전체 진행을 맡겼다면 허용된 후속 작업을 계속하고, 아직 정해지지 않은 핵심 선택이나 모순이 결과를 바꿀 때만 필요한 판단을 요청한다.

쓰기 권한이 없거나 사용자가 파일을 원하지 않으면 같은 Markdown 형식으로 대화에 제공한다. 정보가 없으면 미확인, 적용되지 않으면 이유와 함께 해당 없음으로 기록한다. 실제로 수행하지 않은 단계와 검증은 완료로 채우지 않는다.

## ID·버전·상태 보존

- E는 근거, C는 사례, P는 문제·Pain, M은 원인 발생 과정, O는 개입 지점, R은 요구, S는 대안, X는 실험 계획, V는 검증이다. 예: `M-01`, `O-01`.
- ID는 해당 문서 안에서 안정적으로 유지한다. 같은 ID가 다른 파일에도 있으면 `문서 경로 + ID`로 구분한다. 행을 삭제했다는 이유로 남은 ID를 다시 매기지 않는다.
- 입력표에는 상대 링크와 사용한 리비전을 기록한다. 예: `02-problem-definition.md / r2 / P-01, M-01, O-02`. 원자료에 리비전이 없으면 날짜·행·대화 턴 등 실제 식별 정보를 쓴다.
- 다음 단계는 입력을 다시 읽고 사용할 항목의 근거·상태를 확인한다. 앞 문서의 “가설”을 근거 없이 “확정”으로 바꾸지 않는다. 계획 X-ID에 실행 증거가 없으면 검증 결과가 아니다.
- 입력이 r1에서 r2로 바뀌면 영향받는 연결을 확인한다. 검토 전에는 재검토 필요로 표시하고, 확인한 뒤 사용 버전과 판단을 함께 갱신한다. 버전 문자열만 바꿔 최신성 검사를 통과시킨 것으로 표현하지 않는다.
- 이미 작성한 후속 문서가 오래된 입력을 사용한다면 영향받는 파일·ID를 알린다. 수정 권한이 있으면 해당 부분을 갱신하되 최초 판단·변경 이유를 남긴다. 후속 단계가 실제로 재수행되지 않았다면 그 결과를 갱신했다고 하지 않는다.
- 단독 시작에서 E/P/O-ID가 없으면 현재 문서에 근거와 식별자를 정의하거나 직접 출처를 적는다. 기존에 없던 상위 문서를 지어내 참조하지 않는다.
